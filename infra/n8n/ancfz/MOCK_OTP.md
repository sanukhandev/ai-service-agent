# ANCFZ local-only OTP mock using n8n Data Tables

This optional P5 development adapter uses **no SMTP**. It is not real OTP delivery or customer verification.

The original five ANCFZ workflows and existing credentials remain unchanged. The mocked delivery workflow shares the same private webhook path as the original SMTP delivery workflow, so **never activate both at once**.

## Behavior

The private, Header Auth POST webhook at /webhook/ancfz/otp-email receives an OTP generated by trusted Node. When the container has APP_ENV=development and ANCFZ_OTP_MOCK_ENABLED=true, it appends an entry to the n8n Data Table named ANCFZ_POC_OTPS. Its columns are ticketId (string), emailMasked (string), otp (string), issuedAt (date), expiresAt (date) and status (string). Expiration is five minutes after receipt. The companion cleanup workflow removes expired rows every minute if that workflow is activated.

The response is **mock_recorded, delivered=false**, without returning the OTP. Execution-data retention is disabled, but the **plaintext test OTP remains temporarily visible in the Data Table to the n8n owner**. Never use real customer OTPs, real payments or production data.

## Local operator setup

Keep the existing N8N_ENCRYPTION_KEY unchanged in the private .env. Add:

    APP_ENV=development
    ANCFZ_OTP_MOCK_ENABLED=true

Apply the environment:

    docker compose --profile workflows up -d --no-deps n8n
    docker compose --profile workflows ps -a

Supply your existing n8n owner API key privately as N8N_API_KEY using the method described in SEEDING.md (never paste it into chat, source files or shell history).

    node scripts/setup-n8n-mock-otp.mjs --dry-run
    node scripts/setup-n8n-mock-otp.mjs --inspect
    node scripts/setup-n8n-mock-otp.mjs --setup
    node scripts/setup-n8n-mock-otp.mjs --inspect

The opt-in installer creates the ANCFZ_POC_OTPS Data Table only when absent, validates the schema of any existing table, imports the **two separate mock workflows inactive** and verifies the result. It does not re-import the baseline five, modify existing credentials, activate workflows, delete rows, reset n8n or touch its SQLite database. Partial imports are inspected and only missing assets may be imported; conflicting names or table schema fail closed.

If the API key lacks Data Table privileges, setup reports API_FORBIDDEN. The n8n Data Tables API must be available. If a prior table has a different schema, do not delete it merely to force the install.

## Activate only in local POC

Open http://localhost/n8n/ and check the following state:

- ANCFZ | Deliver Payment OTP (Node Generated): INACTIVE (original SMTP).
- ANCFZ | MOCK OTP Data Table Delivery (LOCAL ONLY): activate for local tests.
- ANCFZ | MOCK OTP Expiry Cleanup (LOCAL ONLY): activate for local tests.

Before activation configure the existing ANCFZ - Node to n8n Webhook Header credential with a strong secret matching Node private webhook authentication. Never use the placeholder credential as a real authorization secret. The mocked delivery is protected by Header Auth and a runtime local-only environment gate; the cleanup workflow has no public webhook.

For a synthetic local smoke test without Node P5, set ANCFZ_N8N_WEBHOOK_SECRET privately in the PowerShell session to the same secret stored in the Header Auth credential. Then run:

    node scripts/test-n8n-mock-otp.mjs

The command generates a random synthetic ticket ID and a six-digit test code internally, submits it only to the private n8n webhook, and prints the ticket ID and expiration time **without printing the code**. Open the ANCFZ_POC_OTPS Data Table to view the test code. The workflow must already be active and correctly configured. Confirm the cleanup deletes the expired row. A disabled cleanup workflow leaves expired rows stored; date expiry is not automatic deletion.

If you prefer a manual n8n test, use a fake UUID (11111111-1111-4111-8111-111111111111), fake email (tester@example.invalid) and a six-digit test code. Never use real recipient identities or any production challenge.

## Security and limitations

The mock stores plaintext **test-only** codes that n8n operators can read. n8n backups and retention settings may preserve data beyond five minutes. Never use it in a shared or production instance, and never infer payment success from a stored code.

The Node P5 OTP issuance, secure hash storage, attempt limiting, one-time consumption, verification and customer authorization flows are not implemented by this add-on. Node remains the authoritative verifier; this workflow only emulates delivery. Returning to SMTP requires disabling both mock workflows, setting ANCFZ_OTP_MOCK_ENABLED=false, and activating the original SMTP delivery only after its credential is verified.
