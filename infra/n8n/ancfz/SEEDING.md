# ANZFC n8n seed — operator instructions

The n8n owner email is **admin@techcarrot.ae**. The requested workspace name is **anzfc** (exact spelling). The existing five workflow definitions remain **ANCFZ**-specific. This seed intentionally uses supported n8n owner provisioning and project-scoped CLI imports, not direct writes to internal n8n SQL schemas.

## Prerequisites

- Node 22+, Docker Compose, and n8n 2.17+ (for environment-managed instance owner).
- A local, uncommitted .env with POSTGRES_PASSWORD, POSTGRES_APP_PASSWORD and a persistent N8N_ENCRYPTION_KEY of 32+ characters.
- n8n Projects feature enabled (registered self-hosted Community or an eligible paid edition). The seed **will fail** if project creation is unavailable; it never silently seeds a personal workspace.
- A private n8n owner API key for the project-import phase. The n8n Public API requires an API key generated by an owner under Settings > n8n API. It is not derivable from an owner password through the supported Public API.
- The specified initial owner password supplied at runtime. **Never commit this password**: it has been shared in chat and should be rotated after initialization.

## Access the editor through local Nginx

The local editor is available at **http://localhost/n8n/** after the workflows
profile is started:

```powershell
docker compose --profile workflows up -d n8n gotenberg
docker compose up -d --build nginx
Start-Process "http://localhost/n8n/"
```

The only published ingress is `127.0.0.1:80`; n8n itself has no host port.
The root app remains `http://localhost/`, and the API remains `/api/`.
`N8N_PATH=/n8n/` tells the browser where editor assets live. Nginx removes
that prefix upstream, so Node's internal `http://n8n:5678/webhook/...` calls,
project seed CLI and n8n's own internal root routes remain unchanged.
n8n webhook, form and MCP ingress URLs are **blocked at Nginx** to prevent
customer-browser requests from bypassing the Node business authorization.
External webhooks need a separate deployment/security design; don't unblock
them just to open the editor.

Keep `N8N_ENCRYPTION_KEY` stable to avoid losing access to saved credentials.
This is an **HTTP localhost-only editor**; never change the Compose port to
`0.0.0.0` or deploy it on a public host without HTTPS and access control.

## Step 1: Set up the owner (PowerShell)

Enter the requested initial password at a hidden prompt and provision the owner.

    $secure = Read-Host "Initial n8n owner password" -AsSecureString
    $bstr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
    try {
        $env:N8N_OWNER_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($bstr)
        node scripts/seed-n8n-anzfc.mjs --stage=owner
    } finally {
        Remove-Item Env:N8N_OWNER_PASSWORD -ErrorAction SilentlyContinue
        [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($bstr)
    }

The command uses a temporary httpd:2.4-alpine container to generate a salted bcrypt hash via stdin, then launches n8n with official N8N_INSTANCE_OWNER_MANAGED_BY_ENV provisioning. Plaintext does not go into the database, an environment file, Compose arguments, Git or the bcrypt-hash variable.

**Existing instances:** If n8n is running **or the persistent n8n-data volume already exists**, owner bootstrap refuses to modify it, even when the container is stopped. A deliberate owner change requires an n8n DB backup and the explicit --allow-owner-update option. If an owner already exists and should not be changed, SKIP owner provisioning.

## Step 2: Create workspace and import (PowerShell)

Log into the PRIVATE n8n editor as the owner and generate an API key (Settings > n8n API). Do not publish the editor/API on an external host port to accomplish this. Then use a private API-key prompt:

    $secureKey = Read-Host "n8n owner API key" -AsSecureString
    $bstr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureKey)
    try {
        $env:N8N_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($bstr)
        node scripts/seed-n8n-anzfc.mjs --stage=import
    } finally {
        Remove-Item Env:N8N_API_KEY -ErrorAction SilentlyContinue
        [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($bstr)
    }

The script creates or finds the project through n8n's authenticated Public API, then imports with the documented --projectId flag (never the personal project):

    n8n import:credentials --input=/workflows/ancfz/credentials.template.json --projectId=PROJECT_ID
    n8n import:workflow --input=/workflows/ancfz/00-otp-email.json --projectId=PROJECT_ID --activeState=false
    n8n import:workflow --input=/workflows/ancfz/01-salesforce-lead.json --projectId=PROJECT_ID --activeState=false
    n8n import:workflow --input=/workflows/ancfz/02-render-pdf.json --projectId=PROJECT_ID --activeState=false
    n8n import:workflow --input=/workflows/ancfz/03-mockgateway-payment-link.json --projectId=PROJECT_ID --activeState=false
    n8n import:workflow --input=/workflows/ancfz/04-mockgateway-payment-verify.json --projectId=PROJECT_ID --activeState=false

It checks for credential-ID and workflow-name collisions before any import and verifies all expected resources afterward. Existing full or partial imports stop the script rather than overwriting or duplicating credentials, because a global name match does not prove project ownership.

## After setup: unlock the owner profile and rotate the initial password

While N8N_INSTANCE_OWNER_MANAGED_BY_ENV is active, n8n locks the owner settings in the UI. After confirming the account was provisioned and you can sign in, re-create n8n **without** the temporary owner-bootstrap variables (the base Compose defaults to false):

    docker compose --profile workflows up -d --force-recreate n8n

This **does not delete the n8n-data volume** and does not reset the owner; it simply disables environment-managed owner updates. Change the initially provided password through n8n's private UI and enable MFA. Keep the encryption key unchanged; changing it without an approved migration will make saved credentials unreadable.

## Safe local checks

    node scripts/seed-n8n-anzfc.mjs --dry-run
    node scripts/check-n8n-anzfc-seed.mjs
    node scripts/check-ancfz-workflows.mjs
    node scripts/check-ancfz-credentials.mjs
    node scripts/check-ancfz-salesforce.mjs

Current Compose n8n uses its own default SQLite database on the n8n-data Docker volume. There is NO direct SQL seed and no user-management:reset or import:entities --truncateTables. The encryption key and n8n-data volume must be backed up together. On new environments, use a licensed/registered edition that allows projects.
